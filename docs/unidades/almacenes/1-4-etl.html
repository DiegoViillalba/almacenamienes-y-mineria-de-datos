3  ETL / ELT con PySpark

3.1 1. ¿Qué es el ETL y por qué importa?

ETL (Extract, Transform, Load) es el proceso que mueve datos desde los sistemas operacionales (OLTP, APIs, logs, archivos) hacia el Data Warehouse, transformándolos en el camino para que sean consistentes, limpios y aptos para el análisis.

Note

Distinción con el Preprocesamiento (Parte II) ETL es ingeniería de datos: opera sobre flujos de producción, terabytes, esquemas fijos, y su salida es reproducible y automatizada. El preprocesamiento analítico (Parte II) toma una vista ya limpia del DW y la transforma para un experimento concreto. El DW es el punto de transferencia entre ambos.

3.1.1 1.1 ETL clásico vs ELT moderno

ETL clásico ELT moderno
Orden Extraer → Transformar → Cargar Extraer → Cargar → Transformar
Dónde transforma Motor ETL externo Dentro del DW / lakehouse
Herramientas Informatica, SSIS, Talend dbt + BigQuery / Snowflake / DuckDB
Ventaja Datos siempre limpios al llegar Aprovechar la potencia del DW columnares
Desventaja Cuello de botella en el motor El DW necesita ser potente y barato

3.1.2 1.2 ¿Por qué PySpark?

Cuando los datos superan la memoria RAM de una sola máquina, pandas deja de ser suficiente. Apache Spark divide el trabajo en particiones que se procesan en paralelo sobre un clúster de nodos, usando un plan de ejecución optimizado (DAG — Directed Acyclic Graph).

PySpark es la API Python de Spark. Con ella puedes escribir transformaciones que escalan de un laptop (modo local) a cientos de nodos (AWS EMR, Databricks, GCP Dataproc) sin cambiar el código.

3.3 3. PySpark: Fundamentos

3.3.1 3.1 SparkSession — el punto de entrada

from pyspark.sql import SparkSession

spark = (SparkSession.builder
    .appName("ETL-Mineria-Datos")
    .master("local[*]")       # local[*] = todos los núcleos de la máquina
    .config("spark.sql.shuffle.partitions", "8")  # reducir para datos pequeños
    .getOrCreate())

spark.version   # '3.5.0'
Note

En producción (Databricks, EMR) el SparkSession ya existe como spark; no necesitas crearlo. El parámetro .master() lo da la plataforma.

3.3.2 3.2 El DataFrame de Spark

Igual que pandas, pero lazy (el cómputo no ocurre hasta que llamas una acción):

# Transformaciones (lazy) — solo construyen el plan
df = spark.read.csv("nyc_taxi.csv", header=True, inferSchema=True)
df2 = df.filter(df.trip_distance > 1.0)
df3 = df2.select("tpep_pickup_datetime", "trip_distance", "total_amount")

# Acción — dispara la ejecución
df3.show(5)
df3.count()       # otro disparo
Concepto Significado
Transformación filter, select, groupBy, join — construyen el DAG
Acción show, count, collect, write — ejecutan el DAG
Partición Unidad de paralelismo; típicamente un archivo Parquet por partición
RDD Capa de bajo nivel; prefiere DataFrame/Dataset salvo casos especiales

3.3.3 3.3 Esquema explícito (mejor práctica)

from pyspark.sql.types import *

schema = StructType([
    StructField("pickup_datetime",  TimestampType(), True),
    StructField("dropoff_datetime", TimestampType(), True),
    StructField("passenger_count",  IntegerType(),   True),
    StructField("trip_distance",    DoubleType(),    True),
    StructField("fare_amount",      DoubleType(),    True),
    StructField("tip_amount",       DoubleType(),    True),
    StructField("total_amount",     DoubleType(),    True),
    StructField("payment_type",     IntegerType(),   True),
])

df = spark.read.csv("yellow_tripdata_2023-01.csv",
                    header=True, schema=schema)

inferSchema=True requiere una pasada completa del archivo; con esquema explícito el proceso es más rápido y sin sorpresas de tipos.

3.5 5. Integración de fuentes heterogéneas: Data Lake → DW

En la práctica, los datos llegan en formatos distintos, con nombres de columnas inconsistentes, tipos incompatibles y niveles de anidamiento variables. Esta sección cubre el conjunto de técnicas que permiten homologar esas fuentes antes de cargarlas al DW.

Haz clic en una capa para ver qué contiene y qué problema resuelve el ETL ahí.

3.5.1 5.1 El problema: fuentes heterogéneas en la Zona RAW

Cuando un Data Lake acumula datos de múltiples fuentes, los problemas típicos son:

Problema Ejemplo real
Formatos distintos ventas en CSV, eventos en JSON, catálogo en XML
Nombres de columna inconsistentes customer_id vs cust_id vs clienteId
Tipos incompatibles "2024-01-15" (string) vs 1705276800 (epoch) vs 20240115 (int)
Anidamiento en JSON {"usuario": {"nombre": "Ana", "dir": {"ciudad": "CDMX"}}}
Encodings distintos UTF-8 vs Latin-1 vs CP1252
Delimitadores no estándar ; en CSV europeo, | en dumps de bases de datos
Nulos representados distinto "", "NULL", "N/A", "\\N", None
Unidades distintas distancia en km vs millas, precios en MXN vs USD

3.5.2 5.2 JSON anidado: aplanar para el DW

El JSON es el formato más común en APIs y event streams, pero el DW necesita una tabla plana (filas × columnas escalares). PySpark ofrece tres herramientas para esto:

from pyspark.sql import SparkSession
from pyspark.sql.functions import (
    col, get_json_object, from_json, to_json,
    explode, explode_outer, inline, flatten,
    struct, to_timestamp
)
from pyspark.sql.types import *

spark = SparkSession.builder.appName("ETL-JSON").master("local[*]").getOrCreate()

# ── Ejemplo: eventos de compra (JSON lines) ───────────────────────────────
# Cada línea es un JSON con objetos anidados y arrays
# {"event_id":"e1","ts":"2024-01-15T10:30:00Z",
#  "user":{"id":42,"city":"CDMX","segment":"premium"},
#  "items":[{"sku":"A01","qty":2,"price":199.0},
#           {"sku":"B03","qty":1,"price":89.5}]}

df_raw = spark.read.json("data/lake/eventos_compra.jsonl")
df_raw.printSchema()
# root
#  |-- event_id: string
#  |-- ts: string
#  |-- user: struct
#  |    |-- id: long
#  |    |-- city: string
#  |    |-- segment: string
#  |-- items: array
#  |    |-- element: struct
#  |    |    |-- sku: string
#  |    |    |-- qty: long
#  |    |    |-- price: double

Técnica 1: acceder a campos anidados con notación punto

# Struct → columnas individuales con notación punto
df_flat = df_raw.select(
    col("event_id"),
    to_timestamp(col("ts")).alias("evento_ts"),
    col("user.id").alias("usuario_id"),
    col("user.city").alias("ciudad"),
    col("user.segment").alias("segmento"),
    col("items")   # el array queda como columna de tipo array
)

Técnica 2: explode — un array → una fila por elemento

# Cada item del array se convierte en una fila independiente
df_items = (df_raw
    .select(
        col("event_id"),
        to_timestamp(col("ts")).alias("evento_ts"),
        col("user.id").alias("usuario_id"),
        explode(col("items")).alias("item")   # <- desdobla el array
    )
    .select(
        col("event_id"),
        col("evento_ts"),
        col("usuario_id"),
        col("item.sku").alias("sku"),
        col("item.qty").alias("cantidad"),
        col("item.price").alias("precio_unitario"),
        (col("item.qty") * col("item.price")).alias("subtotal")
    )
)
df_items.show(5)
# +--------+-------------------+----------+----+--------+---------------+--------+
# |event_id|evento_ts          |usuario_id|sku |cantidad|precio_unitario|subtotal|
# +--------+-------------------+----------+----+--------+---------------+--------+
# |e1      |2024-01-15 10:30:00|42        |A01 |2       |199.0          |398.0   |
# |e1      |2024-01-15 10:30:00|42        |B03 |1       |89.5           |89.5    |
Note

explode elimina filas con array vacío o nulo. Usa explode_outer si quieres conservarlas como fila con item = null.

Técnica 3: JSON embebido como string → parsear con esquema explícito

En muchos pipelines el JSON llega como una columna de texto dentro de otro CSV o tabla (columna tipo STRING con JSON serializado):

# CSV con una columna "payload" que es un JSON serializado como string
# event_id,payload
# e1,"{\"user_id\":42,\"amount\":288.5,\"currency\":\"MXN\"}"

df_csv = spark.read.csv("data/lake/events_flat.csv", header=True)

# Definir el esquema del JSON embebido
payload_schema = StructType([
    StructField("user_id",  LongType(),   True),
    StructField("amount",   DoubleType(), True),
    StructField("currency", StringType(), True),
])

# Parsear la columna string → struct tipado
df_parsed = (df_csv
    .withColumn("payload_struct",
                from_json(col("payload"), payload_schema))
    .select(
        col("event_id"),
        col("payload_struct.user_id").alias("usuario_id"),
        col("payload_struct.amount").alias("monto"),
        col("payload_struct.currency").alias("moneda")
    )
)

Técnica 4: get_json_object — extracción selectiva con JSONPath

Cuando solo necesitas algunos campos de un JSON muy profundo sin parsear el esquema completo:

df_select = df_csv.select(
    col("event_id"),
    get_json_object(col("payload"), "$.user_id").cast("long").alias("usuario_id"),
    get_json_object(col("payload"), "$.amount").cast("double").alias("monto"),
    get_json_object(col("payload"), "$.currency").alias("moneda"),
)

3.5.3 5.3 CSV heterogéneo: normalización de esquema entre fuentes

Un escenario muy común: el mismo tipo de dato llega de tres sistemas distintos con nombres de columna y tipos diferentes. El ETL debe producir una tabla unificada.

# ── Fuente 1: sistema ERP (México) ───────────────────────────────────────
# cust_id,fecha_pedido,monto_mxn,desc_pct
# 1001,15/01/2024,3500.00,0.10

# ── Fuente 2: sistema CRM (EE.UU.) ───────────────────────────────────────
# CustomerID,OrderDate,AmountUSD,Discount
# 1001,2024-01-15,175.00,10

# ── Fuente 3: event log (JSON lines) ─────────────────────────────────────
# {"cliente":1001,"ts":"2024-01-15T10:30:00Z","total":{"mxn":3500,"usd":175},"dcto":0.10}

from pyspark.sql.functions import (
    col, to_date, to_timestamp, lit, round as spark_round
)

TIPO_CAMBIO_MXN_USD = 17.0  # tasa de ejemplo

# Fuente 1: ERP
df_erp = (spark.read
    .option("header", True)
    .option("encoding", "UTF-8")
    .csv("data/lake/erp_pedidos.csv")
    .select(
        col("cust_id").cast("long").alias("cliente_id"),
        to_date(col("fecha_pedido"), "dd/MM/yyyy").alias("fecha"),
        col("monto_mxn").cast("double").alias("monto_mxn"),
        spark_round(col("monto_mxn").cast("double") / TIPO_CAMBIO_MXN_USD, 2).alias("monto_usd"),
        col("desc_pct").cast("double").alias("descuento"),
        lit("ERP").alias("fuente")
    )
)

# Fuente 2: CRM
df_crm = (spark.read
    .option("header", True)
    .option("encoding", "Latin-1")   # encoding diferente
    .csv("data/lake/crm_orders.csv")
    .select(
        col("CustomerID").cast("long").alias("cliente_id"),
        to_date(col("OrderDate"), "yyyy-MM-dd").alias("fecha"),
        spark_round(col("AmountUSD").cast("double") * TIPO_CAMBIO_MXN_USD, 2).alias("monto_mxn"),
        col("AmountUSD").cast("double").alias("monto_usd"),
        (col("Discount").cast("double") / 100).alias("descuento"),  # % → fracción
        lit("CRM").alias("fuente")
    )
)

# Fuente 3: Event log JSON
payload_schema_ev = StructType([
    StructField("cliente",  LongType(), True),
    StructField("ts",       StringType(), True),
    StructField("total",    StructType([
        StructField("mxn", DoubleType(), True),
        StructField("usd", DoubleType(), True),
    ]), True),
    StructField("dcto",     DoubleType(), True),
])

df_events = (spark.read.schema(payload_schema_ev).json("data/lake/events.jsonl")
    .select(
        col("cliente").alias("cliente_id"),
        to_date(to_timestamp(col("ts"))).alias("fecha"),
        col("total.mxn").alias("monto_mxn"),
        col("total.usd").alias("monto_usd"),
        col("dcto").alias("descuento"),
        lit("EVENT").alias("fuente")
    )
)

# ── Unión de las tres fuentes con esquema homologado ──────────────────────
df_unificado = df_erp.unionByName(df_crm).unionByName(df_events)

print(f"ERP:    {df_erp.count():>8,} registros")
print(f"CRM:    {df_crm.count():>8,} registros")
print(f"Events: {df_events.count():>8,} registros")
print(f"Total:  {df_unificado.count():>8,} registros")

df_unificado.printSchema()
df_unificado.groupBy("fuente").count().show()
Warning

unionByName une columnas por nombre, no por posición. Si una fuente tiene una columna extra que las otras no, usa unionByName(df2, allowMissingColumns=True) para rellenarla con null.

3.5.4 5.4 Normalización de tipos y valores nulos heterogéneos

from pyspark.sql.functions import (
    when, trim, upper, lower, regexp_replace,
    coalesce, nanvl, col
)

# ── Nulos representados como strings ─────────────────────────────────────
NULLS_COMO_STRING = ["NULL", "N/A", "\\N", "None", "nan", "", " "]

def limpiar_nulos(df):
    for c in df.columns:
        if dict(df.dtypes)[c] == "string":
            df = df.withColumn(c,
                when(trim(col(c)).isin(NULLS_COMO_STRING), None)
                .otherwise(trim(col(c)))
            )
    return df

df_limpio = limpiar_nulos(df_unificado)

# ── Normalización de texto ────────────────────────────────────────────────
df_texto = (df_limpio
    # quitar acentos y caracteres especiales en columnas de texto
    .withColumn("ciudad",
        regexp_replace(upper(trim(col("ciudad"))),
                       "[ÁÉÍÓÚÜ]", lambda m: {"Á":"A","É":"E","Í":"I",

    when(col("unidad") == "mi",  col("distancia") * 1.60934)
    .when(col("unidad") == "km", col("distancia"))
    .when(col("unidad") == "m",  col("distancia") / 1000.0)
    .otherwise(None)
)

# ── Fechas en múltiples formatos → timestamp estándar ────────────────────
from pyspark.sql.functions import coalesce, to_timestamp

def parse_fecha_multiple(col_name):
    formatos = [
        "yyyy-MM-dd'T'HH:mm:ssX",   # ISO 8601 con timezone
        "yyyy-MM-dd HH:mm:ss",       # datetime sin timezone
        "dd/MM/yyyy",                # fecha europea
        "MM/dd/yyyy",                # fecha americana
        "yyyyMMdd",                  # compacto
    ]
    return coalesce(*[to_timestamp(col(col_name), fmt) for fmt in formatos])

df_fechas = df_raw.withColumn("fecha_std", parse_fecha_multiple("fecha_raw"))

3.5.6 5.6 Conversión JSON (Data Lake) → Parquet (DW): pipeline completo

Este es el patrón más frecuente en la industria: el Data Lake almacena eventos en JSON; el DW los consume como Parquet particionado y tipado.

from pyspark.sql import SparkSession
from pyspark.sql.functions import (
    col, explode, to_timestamp, to_date,
    lit, trim, when, coalesce
)
from pyspark.sql.types import *

spark = (SparkSession.builder
    .appName("lake-to-dw")
    .master("local[*]")
    .config("spark.sql.shuffle.partitions", "8")
    .getOrCreate())

# ─── EXTRACT ──────────────────────────────────────────────────────────────
# Data Lake: JSON semiestructurado con anidamiento
schema_raw = StructType([
    StructField("event_id",   StringType(),  False),
    StructField("ts",         StringType(),  True),
    StructField("version",    IntegerType(), True),
    StructField("user", StructType([
        StructField("id",       LongType(),   True),
        StructField("city",     StringType(), True),
        StructField("segment",  StringType(), True),
        StructField("country",  StringType(), True),
    ]), True),
    StructField("items", ArrayType(StructType([
        StructField("sku",      StringType(), True),
        StructField("category", StringType(), True),
        StructField("qty",      IntegerType(), True),
        StructField("price_usd",DoubleType(),  True),
    ])), True),
    StructField("payment", StructType([
        StructField("method",   StringType(), True),
        StructField("currency", StringType(), True),
        StructField("fx_rate",  DoubleType(),  True),  # tasa vs USD
    ]), True),
])

df_raw = spark.read.schema(schema_raw).json("data/lake/raw/eventos/")

print(f"Registros en lago: {df_raw.count():,}")


# ─── TRANSFORM: aplanar + normalizar + explode ────────────────────────────
df_items = (df_raw
    # Explotar el array de items (1 evento → N filas)
    .withColumn("item", explode(col("items")))
    # Aplanar structs anidados
    .select(
        col("event_id"),
        to_timestamp(col("ts")).alias("evento_ts"),
        to_date(to_timestamp(col("ts"))).alias("fecha"),
        col("user.id").cast("long").alias("usuario_id"),
        trim(col("user.city")).alias("ciudad"),
        trim(col("user.segment")).alias("segmento"),
        coalesce(col("user.country"), lit("MX")).alias("pais"),
        col("item.sku").alias("sku"),
        col("item.category").alias("categoria"),
        col("item.qty").cast("integer").alias("cantidad"),
        col("item.price_usd").alias("precio_usd"),
        # Convertir a moneda local usando la tasa del evento
        (col("item.price_usd") * col("payment.fx_rate")).alias("precio_local"),
        col("payment.method").alias("metodo_pago"),
        col("payment.currency").alias("moneda"),
        # Subtotales
        (col("item.qty") * col("item.price_usd")).alias("subtotal_usd"),
        (col("item.qty") * col("item.price_usd") *
         col("payment.fx_rate")).alias("subtotal_local"),
    )
    # Filtros de calidad
    .filter(col("cantidad") > 0)
    .filter(col("precio_usd") > 0)
    .filter(col("evento_ts").isNotNull())
)

# Añadir columnas de particionamiento derivadas del timestamp
from pyspark.sql.functions import year, month, dayofmonth
df_final = (df_items
    .withColumn("anio",  year("fecha"))
    .withColumn("mes",   month("fecha"))
    .withColumn("dia",   dayofmonth("fecha"))
)


# ─── LOAD: Parquet particionado en el DW ─────────────────────────────────
DW_PATH = "output/dw/hechos_ventas_items/"

(df_final
    .write
    .mode("overwrite")
    .partitionBy("anio", "mes", "dia")
    .parquet(DW_PATH))

# Verificar
df_dw = spark.read.parquet(DW_PATH)
print(f"\nRegistros en DW:   {df_dw.count():,}")
print(f"Columnas:          {len(df_dw.columns)}")
df_dw.printSchema()

# Vista rápida de calidad
df_dw.createOrReplaceTempView("hechos")
spark.sql("""
    SELECT
        pais, segmento, moneda,
        COUNT(*)             AS n_items,
        SUM(subtotal_usd)    AS ingreso_usd,
        AVG(precio_usd)      AS precio_prom_usd
    FROM hechos
    GROUP BY pais, segmento, moneda
    ORDER BY ingreso_usd DESC
""").show(truncate=False)

spark.stop()

3.9 9. Pipeline ETL completo

Ahora unimos Extract + Transform + Load en una función reutilizable:

from pyspark.sql import SparkSession, DataFrame
from pyspark.sql.functions import (
    col, hour, dayofweek, month, when,
    spark_round as _round
)
import logging

logging.basicConfig(level=logging.INFO)
log = logging.getLogger("ETL-Taxi")


def extract(spark: SparkSession, path: str) -> DataFrame:
    log.info(f"Leyendo {path}")
    return spark.read.parquet(path)


def transform(df: DataFrame) -> DataFrame:
    log.info("Transformando...")
    return (df
        .filter(col("trip_distance") > 0)
        .filter(col("fare_amount").between(2.5, 500))
        .filter(col("passenger_count").between(1, 6))
        .fillna({"passenger_count": 1})
        .withColumn("hora",      hour("tpep_pickup_datetime"))
        .withColumn("dia",       dayofweek("tpep_pickup_datetime"))
        .withColumn("mes",       month("tpep_pickup_datetime"))
        .withColumn("duracion",
            (col("tpep_dropoff_datetime").cast("long") -
             col("tpep_pickup_datetime").cast("long")) / 60)
        .filter(col("duracion").between(1, 180))
        .withColumn("propina_pct",
            when(col("fare_amount") > 0,
                 _round(col("tip_amount")/col("fare_amount")*100, 1))
            .otherwise(0.0))
    )


def load(df: DataFrame, output_path: str) -> None:
    log.info(f"Escribiendo en {output_path}")
    (df.write
        .mode("overwrite")
        .partitionBy("mes", "dia")
        .parquet(output_path))
    log.info("¡ETL completo!")


if __name__ == "__main__":
    spark = (SparkSession.builder
        .appName("ETL-NYC-Taxi")
        .master("local[*]")
        .config("spark.sql.shuffle.partitions", "16")
        .getOrCreate())

    raw   = extract(spark, "data/yellow_tripdata_2023-01.parquet")
    clean = transform(raw)
    load(clean, "output/taxi_etl/")

dbt (data build tool) separa la transformación del pipeline técnico: defines las transformaciones como modelos SQL, y dbt se encarga de ejecutarlos en el orden correcto, con pruebas automáticas y documentación.

SELECT
    VendorID                    AS vendor_id,
    tpep_pickup_datetime        AS pickup_at,
    trip_distance,
    fare_amount,
    tip_amount,
    total_amount,
    payment_type
FROM {{ source('raw', 'yellow_taxi') }}
WHERE trip_distance > 0
  AND fare_amount   > 2.5
-- models/marts/fct_viajes_diarios.sql
SELECT
    DATE(pickup_at)             AS fecha,
    HOUR(pickup_at)             AS hora,
    COUNT(*)                    AS n_viajes,
    AVG(total_amount)           AS ticket_prom,
    SUM(total_amount)           AS ingreso_total
FROM {{ ref('stg_viajes') }}
GROUP BY 1, 2
# models/schema.yml — pruebas automáticas de calidad
models:
  - name: stg_viajes

      - name: vendor_id
        tests: [not_null]

3.12 12. Orquestación con Apache Airflow

En producción, los pipelines ETL se ejecutan automáticamente según un calendario. Airflow define estos flujos como DAGs de Python:

from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime, timedelta

def extraer(**ctx):
    mes = ctx['logical_date'].strftime("%Y-%m")
    print(f"Extrayendo mes {mes}...")
    # aquí va el código de extracción

def transformar(**ctx): ...
def cargar(**ctx): ...
def validar(**ctx): ...

with DAG(
    dag_id="etl_nyc_taxi_mensual",
    start_date=datetime(2023, 1, 1),
    schedule_interval="0 3 1 * *",  # el día 1 de cada mes a las 3 AM
    catchup=False,
    default_args={"retries": 2, "retry_delay": timedelta(minutes=5)},
) as dag:

    t_extract   = PythonOperator(task_id="extraer",     python_callable=extraer)
    t_transform = PythonOperator(task_id="transformar", python_callable=transformar)
    t_load      = PythonOperator(task_id="cargar",      python_callable=cargar)
    t_validate  = PythonOperator(task_id="validar",     python_callable=validar)

    t_extract >> t_transform >> t_load >> t_validate
Tip

Alternativas a Airflow: - Prefect — más Python-nativo, sin XML/YAML, fácil para equipos pequeños. - Dagster — fuerte en observabilidad y gestión de assets de datos. - Para empezar: Prefect + PySpark local → luego migrar a Airflow en producción.
